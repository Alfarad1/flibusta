# Docker-контейнер для локальной копии Флибусты.

Отображение книг, поиск по заголовкам, сборникам, авторам, жанрам. Открываются в браузере форматы fb2, epub, pdf, djvu, docx, rtf, mobi, txt, html. Для fb2 и epub — читалка с настройками и позицией чтения у каждого пользователя.

У каждого члена семьи свой пользователь: свои полки, статусы книг («Хочу прочитать», «Читаю», «Прочитано», «Бросил»), избранные авторы и серии, позиция чтения.

Встроенный сервис OPDS для читалок.

## Установка:

1. Установить сервисы docker для вашего сервера.
2. Разместить файлы проекта в каталог на сервере.
3. Для выполнения обновления необходимо разместить фалы дампа Флибусты (*.sql) в каталог FlibustaSQL.
4. Файлы архивов Флибусты (*.zip) размещайте на диске с книгами: в корне репозитория self-hosted по умолчанию это `/mnt/5977acb808a7/books` (том в `docker-compose.yml` и `docker-compose.stack.yml`).
5. Выполнить docker-compose build
6. Выполнить docker-compose up -d
7. Локальный портал будет доступен на порту 27100. Доступен также OPDS каталог: /opds/
8. Выполнить "Обновление базы" через пункт меню "Сервис"

Каталоги FlibustaSQL, cache и их подкаталоги должны иметь права на запись для контейнера. Скрипты в каталоге /application/tools/ должны иметь права на выполнение.

Для обновления базы с новыми файлами выполнить пункты 3, 4, 5, 9

## Поиск

Строка поиска на главной ищет по названию книги, авторам и сериям сразу, слова можно вводить в любом порядке и не до конца («гарри потт», «пелевин generation»). Учитываются словоформы, ё и е не различаются. Сначала показываются точные совпадения названия. Если ничего не нашлось, сайт подскажет, не скрыли ли книги фильтры, и предложит похожие названия и авторов (опечатки). Тот же поиск работает в OPDS (`/opds/search?q=...`).

Результаты можно сортировать: новые поступления, по названию, по году издания, по рейтингу (при поиске по умолчанию — по релевантности).

Издания одной книги — разные файлы, переиздания и переводы с тем же названием и теми же авторами — в результатах поиска, на странице автора, переводчика и серии показываются одной карточкой: основным выбирается издание с файлом, в fb2, с бо́льшим числом оценок, остальные — списком «Ещё N изданий» (год, формат, размер, переводчик, серия, оценка). На странице книги тот же список — «Другие издания». Кнопка «Без повторов / Все издания» переключает группировку. Разные тома с одинаковым названием (по номеру в серии) и «Том 1», «Стихотворения», «Избранное» из разных собраний не склеиваются.

## Рейтинги, рекомендации, переводчики

Из дампов Флибусты используются оценки читателей (`librate`) — средний балл на карточке книги и сортировка «По рейтингу» (байесовская оценка: книга с одной пятёркой не обгоняет книгу с сотней оценок), рекомендации (`librecs`) — блок «Читатели этой книги также рекомендуют» на странице книги, переводчики (`libtranslator`) — на карточке книги и фильтр «Переводы» на странице переводчика, объединённые редакции (`libjoinedbooks`) — у заменённой книги ссылка на новую редакцию, её оценки и рекомендации переносятся на новую.

Поисковый индекс, рейтинги, рекомендации и группы изданий перестраиваются при «Обновлении базы». После обновления самого приложения их нужно перестроить один раз вручную: кнопка **«Поисковый индекс»** в меню **«Сервис»** (или `tools/app_update_vectors.sh` в контейнере php-fpm). До этого сайт работает, но без рейтингов, рекомендаций и группировки изданий.

## Пользователи

Сайт рассчитан на своих, поэтому паролей нет. Каталог, поиск и скачивание доступны без входа. Для полки, избранного и сохранения позиции чтения нужно выбрать себя на странице **«Кто читает?»** (`/users/`, кнопка справа в меню) или создать нового пользователя — достаточно имени. Выбор запоминается в браузере на год. Там же можно выйти, сменить имя или удалить себя (для подтверждения нужно ввести своё имя): удаляются полки, статусы, избранное и прогресс чтения.

Прежние «книжные полки» стали пользователями с тем же содержимым. Если две полки назывались одинаково, ко второй добавляется номер: «Маша (2)». Таблицы пользователей создаются и обновляются автоматически при первом открытии сайта после обновления приложения (номер миграции хранится в таблице `app_schema`).

## Полки и статусы

На обложке каждой книги (для вошедшего пользователя) две кнопки: сердце — добавить на полку «Избранное», закладка — меню, где выбирается статус книги и полки, на которые её положить. Статус у книги один, полок может быть сколько угодно. Статус, поставленный одному изданию, виден и на остальных изданиях этой книги (кнопка контурная, с подсказкой «отмечено в другом издании»).

Раздел **«Полка»** (`/fav/`): «Продолжить чтение» (книги со статусом «Читаю», последние открытые первыми), списки по статусам, полки и создание новой, избранные авторы и серии. На странице полки — сортировка, листание, переименование и удаление (книги остаются в библиотеке, «Избранное» удалить нельзя). Полки и статусы остальных членов семьи можно смотреть (переключатель вверху), но не менять. «Продолжить чтение» показывается и на главной, когда не задан поиск и фильтры.

Старое «избранное» книг переносится на полку «Избранное», избранные авторы и серии остаются как были.

OPDS-каталог открыт без входа: в разделе «Книжные полки» перечислены пользователи, у каждого — его полки и списки по статусам.

## Читалка

Книга открывается кнопкой **«Читать»** на странице книги (или «Продолжить чтение · 37%», если её уже начали) — на отдельной странице `/read/<id>` без меню сайта. Сверху панель: назад к книге, название, процент прочитанного, оглавление и настройки; при прокрутке вниз она прячется, при прокрутке вверх (на телефоне — по касанию текста) появляется снова.

- **FB2** показывается своей вёрсткой. Настройки: тема (день, сепия, ночь), шрифт с засечками или без, размер, межстрочный интервал, ширина колонки, выравнивание по ширине с переносами. Оглавление строится по заголовкам разделов, сноски открываются во всплывающем окне (и собраны в конце книги). Клавиши: пробел, PageDown, → — страница вперёд; Shift+пробел, PageUp, ← — назад; + и − — размер шрифта; T — оглавление; S — настройки.
- **EPUB** — через epub.js с теми же настройками и оглавлением книги.
- PDF, DjVu, MOBI, RTF, DOCX, TXT, HTML — встроенными просмотрщиками, без настроек и позиции.

Настройки хранятся в браузере — свои на каждом устройстве (на телефоне обычно нужен другой размер шрифта). Позиция чтения хранится у пользователя на сервере и открывается на любом устройстве. Для FB2 это номер абзаца и место внутри него, поэтому позиция не съезжает при смене шрифта, повороте телефона или подгрузке картинок; для EPUB — CFI. Когда книгу начинают читать, ей ставится статус «Читаю» (если не было статуса или был «Хочу прочитать»), в конце книги есть кнопка «Отметить „Прочитано“».

FB2 разбирается один раз: текст, оглавление и картинки складываются в `cache/reader` (очищается кнопкой «Очистить кэш» в «Сервисе»). В текст попадают только элементы FB2, HTML и скрипты внутри книги выводятся как текст. Если файла нет в архиве или он не разбирается, показывается сообщение и ссылка на скачивание.

## Переменные окружения для docker-compose (docker-compose environmnet variables):

Параметры базы данных можно определить в docker-compose.yml. 

Образ может использовать следующие переменные окружения

1. `FLIBUSTA_DBUSER` user базы данных. По умолчанию (если переменная не определена в файле) flibusta
2. `FLUBUSTA_DBNAME` имя схемы ( инстанса) базы данных. По умолчанию (если переменная не определена в файле) flibusta
3. `FLIBUSTA_DBTYPE` тип базы данных. В текущей версии поддерживается только postgres
4. `FLIBUSTA_DBHOST` имя хоста на которой установлена база данных. В докере по умолчанию совпадает с именем сервиса 
                        определяющего базу данных. По умолчанию postgres
5. `FLIBUSTA_DBPASSWORD`  пароль user базы данных. См. обсуждение в следующем абзаце. По умолчанию flibusta


Best practices docker compose не рекомендуют хранить пароль в переменной  ( и тем более не рекомендуется задавать пароль в коде).
Для хранения паролей в есть механизм secrets. Можно создать текстовой файл содержащий единственную 
строчку с паролем и указать полный путь к нему в глобальном разделе secrets. Обратите внимание на premissions файла - он должен быть
доступен для чтения для php из образа, в идеале только ему. Юзер под которым бежит php-fpm в pool www-data ( user id 82). Это стандартный 
user из официального образа. Возможно он не существует на вашей системе. Можно дать числовой  uid файлу если нет желания или возможности создать user. достаточно выполнить `sudo chown 82 /path/to/file`  
   
## Конфигурация docker container для работы с reverse proxy и внешним сервером базы данных

Docker compose файл, используемый по умолчанию, поднимает веб сервер и базу данных для локального зеркала Флибусты. Однако, часто вебсервер и база данных уже работают на NAS. 
В таком случае можно использовать их и сэкономить ресурсы сервера не поднимая несколько инстансов параллельно. Кроме того, использование централизованного reverse proxy может дать некотрые дополнительные преимущества. Папка application/tools/external_services_config 
содержит необходимые скрипты и конфигурационные файлы для работы в такой конфигурации, а  [README](application/tools/external_services_config/README.md) описывает процесс конфигурации.

## Self-hosted стек (общий Postgres, только VPN, nginx-internal)

Файл **`docker-compose.stack.yml`** поднимает только **php-fpm** в сети Docker **`internal`** (тот же Postgres, что `infrastructure/postgres`). Обратный прокси — **`nginx-internal`** в корне репозитория; URL приложения: **`/mylib`** (см. `FLIBUSTA_WEBROOT` и `application/tools/external_services_config/flibusta.conf`). На хост проброшен порт **8880** → HTTP `nginx-internal` (в корневом `nginx/docker-compose.yml`). Flibusta: **`http://<сервер>:8880/mylib/`**.

1. Создайте сеть `internal`, поднимите Postgres и **nginx-internal** (см. корневой README репозитория).
2. Скопируйте **`secrets/postgres_admin_pwd.txt.example`** → **`secrets/postgres_admin_pwd.txt`** (одна строка: `POSTGRES_PASSWORD` из корневого `.env` для `POSTGRES_USER`). Файлы `secrets/*.txt` и `.env` в git не хранятся.
3. Скопируйте **`secrets/flibusta_pwd.txt.example`** → **`secrets/flibusta_pwd.txt`** — пароль роли приложения `flibusta` (после первого запуска должен совпадать с тем, что записал entrypoint). Для standalone-стека также: **`.env.example`** → **`.env`**.
4. Положите дампы SQL в **`FlibustaSQL`**, архивы *.zip — в каталог на хосте, смонтированный в `/application/flibusta` (по умолчанию `/mnt/5977acb808a7/books`). Обложки не-FB2 книг и фото авторов берутся из `cache/lib.b.attached.zip` и `cache/lib.a.attached.zip` (скачивает `getcovers.sh`); без них показываются заглушки.
5. Из **корня** репозитория self-hosted:

```bash
docker compose --env-file .env -f books/flibusta_web/flibusta/docker-compose.stack.yml build
docker compose --env-file .env -f books/flibusta_web/flibusta/docker-compose.stack.yml up -d
```

Переменная **`POSTGRES_USER`** из корневого `.env` передаётся в контейнер как **`POSTGRES_ADMIN_USER`** для первичной инициализации БД. При необходимости скопируйте [`.env.stack.example`](.env.stack.example) и укажите `APPUSER_PUID` / `APPUSER_PGID` / `TIME_ZONE_VALUE`. PUID/PGID применяются при сборке образа: php-fpm работает с этим uid, поэтому `cache` и `FlibustaSQL` должны принадлежать этому пользователю.

После запуска выполните **«Обновление базы»** в меню **«Сервис»** в веб-интерфейсе.
